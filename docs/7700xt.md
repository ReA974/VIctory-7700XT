# Ryzen 5 5600X + RX 7700 XT : mode d'emploi

Toutes les commandes se lancent dans PowerShell, depuis le dossier du dépôt :

```powershell
cd 'C:\Users\diabl\Documents\Mes documents\recomp gta 6\VIctory-7900XTX'
```

Si PowerShell refuse les scripts, préfixer par `powershell -NoProfile -ExecutionPolicy Bypass -File`
(c'est ce que font les commandes ci-dessous).

## 1. Compiler (après chaque changement de code)

```powershell
cargo build --locked --release -p victory
```

La build de diagnostic (journaux de coûts, profileur) :

```powershell
cargo build --locked --profile diag -p victory --features diagnostics
```

`.cargo/config.toml` compile pour Zen 3 (`target-cpu=znver3`) : l'exe ne tourne que sur un processeur
qui a AVX2/BMI2/FMA.

## 2. Préparer les shaders et les pipelines (une fois, puis après un changement du traducteur, du pilote ou de PORT_CBV)

```powershell
.\target\release\victory.exe shaders G:\savegta5wallah\tktmonreuf
```

```powershell
$env:VICTORY_PORT_CONSTANTS='1'; $env:VICTORY_PORT_DESCRIPTORS='1'; $env:VICTORY_PORT_GUARD='1'; $env:VICTORY_PORT_JOURNAL='1'; .\target\release\victory.exe warm
```

Avec `-Cbv` (voir plus bas), faire les deux avec `$env:VICTORY_PORT_CBV='1'` en plus, sinon l'image
reste noire plusieurs minutes au premier lancement. `warm` reprend là où il s'est arrêté.

## 3. Jouer

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\play-7700xt.ps1 -Exe 'G:\savegta5wallah\tktmonreuf\game_scarlett_master.exe'
```

Par défaut : Series X en 1080p natif, éclairage corrigé, 6 threads de traduction, buffers ≥1 Mo en VRAM,
REAPER, et A appuyé tout seul pendant 5 min (choix de profil, cinématique). Options utiles :

| Option | Effet |
|---|---|
| `-RenderScale 0.83` | rendu interne 1600x900 au lieu de 1080p natif : ~5 ms de moins par image, un peu moins net |
| `-AutoA 0` | ne pas appuyer sur A tout seul |
| `-SeriesS` | ancien profil Series S (720p agrandi) |
| `-ThinThreads 6` | threads de traduction (6 = mieux mesuré sur 5600X) |
| `-Build diag -Log <fichier>` | build de diagnostic avec le détail des coûts par image dans le fichier |
| `-More @{VICTORY_XXX='1'}` | n'importe quel autre réglage `VICTORY_` |

## 4. Mesurer (médiane des ms par image, 90 s dans le monde, capture dans tools\shots)

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File '..\tools\bench.ps1' -Name essai1
```

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File '..\tools\bench.ps1' -Name essai2 -PlayArgs '-RenderScale 0.83'
```

Le banc lance le jeu, attend le monde, attend 10 s, mesure, capture et ferme. Une seule mesure à la fois
(verrou `tools\bench.lock`) ; pas de compilation pendant une mesure. Ne pas mesurer pendant un `warm`.

Lire le détail d'un journal diag :

```powershell
& '..\tools\stats.ps1' -Log <fichier> -Patterns ' fps, ','submissions prepared by a thread','preparing per frame, the submitting','card.s clock'
```

## Mesures (prison, 1080p natif sauf mention)

| Configuration | ms par image | fps |
|---|---|---|
| play.ps1 d'origine, 8 threads | 77 | 12,9 |
| 6 threads de traduction | 65 | 15,4 |
| + build Zen 3 | 62 | 16,1 |
| + REAPER | 61 | 16,4 |
| + rendu 1600x900 (`-RenderScale 0.83`) | 57 | 17,6 |

Essayé sans gain : Resizable BAR (`VICTORY_WINDOWS_BAR_MB`), deux images en vol (`SUBMIT_FRAMES=2`),
file de copie (`UP_QUEUE=1`), priorité de la soumission (`VICTORY_SUBMIT_PRIORITY=high`), 5 threads,
les optimisations de la traduction de la session parallèle (gardées, interrupteurs à 0 pour couper).

Ce qui fixe l'image : le thread de soumission (~59 ms de travail par image) et la carte (84 % en 1080p
natif). Prochaines pistes : PORT_CBV préparé d'avance (-4,7 ms chez le développeur), puis ne rapatrier
de la carte vers la RAM que ce que le processeur lit vraiment.
